# 更新界面与运行形态显示设计

## 目标

改善“检查更新”区域的视觉层级，并确保下载操作严格匹配当前运行形态和版本状态：只有发现新版本后才出现操作；安装版只显示增量更新，便携版只显示便携版下载。

## 运行形态

主进程根据 Electron/NSIS 提供的运行环境判断 `installed` 或 `portable`，通过更新检查结果返回 `runtimeType`。渲染端不使用可执行文件名猜测。开发环境标记为 `development`，只允许检查和预览附件，不允许执行安装或自动退出。

## 状态与显示规则

- 初始状态：显示线路选择和“检查更新”，不显示任何下载按钮。
- 检查中：主按钮显示旋转图标和“正在检查…”，按钮禁用。
- 无新版：显示绿色“当前已是最新版本”，不显示附件列表或下载按钮。
- 检查失败：恢复“重新检查”，保留切换线路提示。
- 安装版发现新版：只显示新版说明和“下载增量更新”；不显示便携版附件。
- 安装版下载完成：显示“立即安装”。
- 便携版发现新版：只显示便携版名称、大小和“选择位置并下载”；不显示安装版附件。
- 下载中：对应按钮禁用，统一进度区显示百分比、已下载量和速度。

## 视觉样式

检查按钮使用现有粉紫品牌色的渐变背景、圆角、轻阴影和清晰焦点环。悬停时轻微上移，按下时回落；禁用态降低饱和度但保持文字可读。状态区使用紧凑卡片布局，版本号为主要信息，线路选择和文件大小为次级信息。成功状态使用低饱和绿色，不使用大面积高亮。

所有按钮使用文本与小型 CSS 图标组合，不增加图片资源或新 UI 依赖。尊重 `prefers-reduced-motion`，在减少动态效果时关闭上浮和旋转动画。

## 接口调整

- 主进程新增 `detectRuntimeType({ app, env })`，返回 `installed|portable|development`。
- `update:check` 返回值增加 `runtimeType`，并只返回当前形态允许展示的附件。
- 安装版 IPC 在非 `installed` 形态拒绝执行；便携版 IPC 在非 `portable` 形态拒绝执行。
- 更新控制器根据 `updateAvailable` 和 `runtimeType` 生成唯一操作按钮。

## 测试与完成标准

增加运行形态检测、附件过滤、无新版隐藏操作、安装版唯一操作、便携版唯一操作和按钮状态测试。运行完整测试与语法检查，构建两种 EXE。功能分支验证通过后快进合并到 `main` 并推送；此视觉与逻辑修正不单独发布新版本，随下一次 Release 发布。
